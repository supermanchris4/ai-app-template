# API

The API contract. The OpenAPI document generated by FastAPI is the machine-readable form; this file is the human-readable form it is generated from.

## Template conventions

These apply to every endpoint. An application extends them and does not remove them.

### Versioning

- Base path `/api/v1`. `/api/health` and the sign-in endpoints under `/api/auth/` are the only unversioned endpoints.
- A breaking change needs a new major version (`/api/v2`).

### Authentication

Every endpoint except `/api/health` and `/api/auth/` requires a caller identity and at least one app role ([50-auth.md](50-auth.md)). The web interface is identified by its session cookie, and state-changing calls also carry `X-CSRF-Token`. Other systems and consumers send `Authorization: Bearer {access token}`. Each endpoint below lists the roles that may call it.

### Paths

Paths name the resource, never the caller. `/api/v1/customers/{id}` and `/api/v1/accounts/{id}` are resources like any other, and one operation serves internal users, external users and systems, with access set by the caller's identity and roles. There are no prefixes such as `/staff/`, `/customer/` or `/external/`. Every operation an external user may call checks that the record belongs to them ([50-auth.md](50-auth.md#authorisation)).

### Content type

Requests and responses are `application/json`, except file uploads, which use `multipart/form-data`.

### Validation

Every request field declares its type, whether it is required, and its permitted length, format or range. Numeric and date fields always have a minimum and maximum. Rules spanning fields or records are checked in the service layer.

### Dates and times

Timestamps are ISO 8601 with an offset. The API returns them in UTC (`2026-10-27T06:05:00Z`) and rejects a timestamp without an offset. Calendar dates are ISO 8601 dates (`2026-10-27`) and carry no time zone.

### Error response

Every error, from validation to unexpected failure, has this shape:

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Human-readable description",
    "details": [
      { "field": "reading_value", "issue": "Must be between 0 and 14" }
    ],
    "correlation_id": "uuid",
    "request_id": "uuid"
  }
}
```

| HTTP status | `code` | When |
|---|---|---|
| 400 | `VALIDATION_ERROR` | The request failed validation |
| 401 | `UNAUTHORIZED` | The token is missing, expired or invalid |
| 403 | `FORBIDDEN` | The token lacks a permitted role, or the record-level check failed |
| 404 | `NOT_FOUND` | The record does not exist |
| 409 | `CONFLICT` | The operation conflicts with the record's state |
| 500 | `INTERNAL_ERROR` | An unexpected error, with no internal detail |

Rate limiting is applied by AWS WAF at CloudFront, which returns 429 before the request reaches the API.

### Pagination

List endpoints use cursor pagination. Query parameters are `limit` (default 50, maximum 200) and `cursor` (an opaque token). Responses have this shape:

```json
{
  "data": [],
  "pagination": { "limit": 50, "has_more": true, "next_cursor": "opaque-token-or-null" }
}
```

### Correlation

A client may send `X-Correlation-ID`; otherwise the API generates one. `X-Correlation-ID` and `X-Request-ID` are returned on every response.

### Explicit operations

Every change is an explicit operation named for what it does (`POST /api/v1/inspections/{id}/approve`), not a generic update of arbitrary fields. Corrections to recorded data require a reason ([31-audit.md](31-audit.md)).

### Template endpoints

| Endpoint | Roles | Notes |
|---|---|---|
| `GET /api/health` | None | [20-api-scaffold.md](20-api-scaffold.md#health-endpoint) |
| `/api/auth/login`, `/callback`, `/session`, `/logout` | None (they establish the session) | [20-api-scaffold.md](20-api-scaffold.md#authentication-and-authorisation) |
| `GET /api/v1/directory/users?search=` | Listed by the application | Optional ([20-api-scaffold.md](20-api-scaffold.md#directory-lookup)). Remove if the application needs no directory lookup. |
