# Web interface

The web interface is a React single-page app, built with Vite and served from S3 through CloudFront (Standard D-03). It is a client of the API and holds no business rules. It is one client among others: screens for external users are clients of the same operations other consumers call (Standard D-18).

## Template conventions

These apply to every application. An application extends them and does not remove them.

The web platform package ([10-architecture.md](10-architecture.md#platform-packages)), provides the parts every application shares: sign-in navigation, the session provider that calls `GET /api/auth/session`, the `RequireRoles` route guard, the API client functions `src/lib/api.ts` builds on (`platformFetch`, `apiRequest` and `ApiError`), the error notice, the environment banner with `loadConfig`, `LocalDate` and `NavLink`. The application writes `src/lib/api.ts`, its pages and its component kit. The package's components use the theme colours `accent`, `destructive` and `muted-foreground`, so the application defines them, and its Tailwind `content` setting includes `node_modules/@supermanchris4/ai-app-platform-web/dist/**/*.js`. Version 0.1 signs people in through the internal provider only (the standard's work plan item F03.5).

| Concern | Convention |
|---|---|
| Language | TypeScript in strict mode |
| Routing | React Router. Pages are routes under `src/pages/`. |
| Sign-in | The API signs people in ([50-auth.md](50-auth.md#web-sign-in-the-api-as-backend-for-frontend)). "Sign in" navigates to `/api/auth/login` with the provider (`internal` or `external`) and the current path. On start, the app calls `GET /api/auth/session` to learn who is signed in. The web interface never receives or stores a token. |
| Route guards | A guard on each route checks the roles returned by `GET /api/auth/session` and decides only what is shown. The API still refuses anything the roles do not allow. |
| API access | Only through `src/lib/api.ts`, which uses the client generated from the API's OpenAPI document. Requests go to the same address, so the browser sends the session cookie. The module adds the `X-CSRF-Token` header to every state-changing request and the correlation ID to every request, and sends the person to sign in again on a 401. Errors surface as `ApiError` with the status and the shared error body. |
| Components | Tailwind and Radix primitives in `src/components/ui/`. Extend this kit; do not add a component library that duplicates it. |
| Configuration | `config.json`, written at deployment, holds only the environment name, so one build serves every environment. The web interface needs no identity settings. |
| Dates | Shown through the shared `LocalDate` component in the formats set under [Date and time formats](#date-and-time-formats). A timestamp is converted to the browser's time zone. A calendar date is shown as it is, without time zone conversion. |
| Environment banner | Shown on every page in every environment except production, naming the environment |
| Confirmation | Any action that cannot be undone asks for confirmation, naming what will happen |
| Accessibility | WCAG 2.2 level AA, from the standard's configuration defaults. Tables have captions and announce their sort order. Every page passes the automated accessibility checks. |
| Errors and states | Every page has loading, empty and error states. Errors show the API's message and the correlation ID for support. |
| Screens for external users | Kept under their own routes, using only the operations external users can call |

## Forbidden

- Calling the API other than through `src/lib/api.ts`
- Calling a directory service, an identity provider or any other service directly; such calls go through the API
- Handling or storing access, ID or refresh tokens, including with MSAL or another sign-in library in the browser
- Business rules or calculations in the web interface, including calculating an outcome the API stores
- Using a role check in the web interface as the only control
- Storing personal information in `localStorage` or `sessionStorage`

## Navigation

Navigation links are rendered with the shared `NavLink` component, shown only to the roles that can use the page.
